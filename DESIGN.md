# DESIGN.md — паспорт дизайна и движения

Единственный документ о визуальном языке «Бизнес Перезагрузка с AI» (Garincha AI-Tech). Токены в коде — `app/globals.css` (`@theme`, `:root`); если документ и код расходятся, исправляется документ или код в том же PR.

Утверждённый референс — вариант 2: тёплая бумажная редакционная страница, карточка гипотезы как физический лист.

## 1. Принципы

1. **Сначала смысл, потом эффект.** Заголовок, подзаголовок и главная кнопка видны и работают сразу, без JavaScript.
2. **Честность важнее убедительности.** Всё непроверенное подписано: «Спрос ещё не проверен», «не проверено», «Демонстрационный пример». Нет обещаний дохода, процентов успеха и выдуманных источников.
3. **Один главный шаг на экране.** На каждой рабочей странице одна основная кнопка (teal), остальные — вторичные.
4. **Бумага, не стекло.** Плотные тёплые поверхности, тонкие линейки, тени как у листа на столе. Никаких неоновых градиентов, glassmorphism и фоновых частиц.
5. **Сохранено — значит на сервере.** Подтверждения «Сохранено» появляются только после ответа сервера.

| `ink-soft` | `#3a3833` | Текст абзацев |

| `rule` / `rule-strong` | `#d3cdc1` / `#b9b2a4` | Линейки, границы полей |

## 3. Типографика

- **Literata** (переменная, ось `opsz`, латиница + кириллица) — заголовки, названия карточек. `font-optical-sizing: auto`.
- **Golos Text** (латиница + кириллица) — интерфейс и текст.
- Шкала: `display` clamp(2.6rem → 4.6rem) / 1.02; `title` clamp(1.9rem → 2.9rem) / 1.08; `subtitle` ≈ 1.5rem; текст 1rem–1.06rem / 1.6; подписи 0.82–0.9rem.
- Eyebrow — Golos 600, uppercase, разрядка 0.16em, teal.
- Шрифты подключены через `next/font` (self-hosted, `display: swap`, предзагрузка обоих подмножеств). Вес ≈ 228 KB woff2. Пробовали убрать ось `opsz` (139 KB), но крупный заголовок становится тяжелее и отходит от референса. Пробовали не предзагружать латиницу — появляется сдвиг макета (CLS 0.008–0.019). Оставлен исходный вариант, CLS 0.

## 4. Сетка, ритм, поверхности

- Контейнер `max-w-[76rem]`, поля 20px → 32px (sm) → 48px (lg); на экранах < 360px шапка сжимается до 16px.
- Вертикальный ритм секций лендинга: 96–128px; рабочих экранов: 40–56px.
- Радиусы: 3px (листы), 6px (поля, панели), 999px (чипы).
- Тени: `--shadow-paper` (лист на столе), `--shadow-lift` (наведение).

## 5. Компоненты

| Класс | Где | Правило |
| --- | --- | --- |
| `.btn-primary` | Одно главное действие | Teal, мин. высота 44px |
| `.btn-secondary` / `.btn-quiet` | Остальные действия | Не конкурируют с primary |
| `.control`, `Field` | Все поля | Подпись над полем, подсказка, ошибка связаны через `aria-describedby` |
| `.chip-*` | Статусы шагов, «не проверено», PRO | Всегда текст, не только цвет |
| `.notice-*` | Сообщения | `role="status"` для успеха, `role="alert"` для ошибок |
| `.panel` | Боковые панели | `paper-raised`, линейка, без тени |
| `.paper` | Карточка гипотезы | Тень листа, лёгкий поворот только на лендинге |
| `<dialog>` | Подтверждение гипотезы | Нативный modal: фокус внутри, Esc закрывает |

Состояния: hover (цвет/тень), `:focus-visible` (кольцо 2px teal со смещением), disabled (0.5 непрозрачности + `cursor: not-allowed`), pending (текст «Сохраняем…», кнопка заблокирована).

## 6. Тон текста

Обращение на «вы», короткие фразы, глаголы действия в кнопках («Выбрать идею», «Подтвердить гипотезу»). Не используем: «гарантированно», «пассивный доход», «AI сделает всё за вас», проценты успеха. Пример всегда подписан как пример.

## 7. Адаптивность и доступность

- Брейкпоинты: 360 / 400 (шапка), 640 `sm`, 768 `md`, 1024 `lg` (сцена: закрепление только от 1024px и при высоте, достаточной для композиции; на ноутбуках с высотой ≤ 820px включается компактный вариант подписей).
- Проверено: 320, 390, 820, 1100×760, 1280×720, 1366×768, 1440×900, 1920×1080, масштаб 200% (720 CSS px) — без горизонтальной прокрутки.
- Порядок фокуса совпадает с визуальным; ссылка «Перейти к содержанию» переводит фокус в основной блок.
- Сцена «Как это работает» декоративна (`aria-hidden`), её смысл продублирован текстом подписей шагов.
- Мобильные рабочие экраны: панель действий закреплена снизу, учитывает `safe-area-inset-bottom`.

## 8. Движение

### Общие правила

- **Длительности.** Микро-переходы (hover, фокус, цвет): 150 мс (`--dur-fast`). Смена состояния экрана (появление шага мастера, уведомление, затемнение подписей): 240 мс (`--dur-base`). Это укладывается в коридоры 120–180 мс и 200–300 мс. Повествовательные появления на лендинге — 550–700 мс, только один раз.
- **Кривые.** `--ease-out-soft` для появлений, `power2.out`/`power3.out` в GSAP, `none` для линии, привязанной к скроллу.
- **Только `transform`, `opacity`, `clip-path`.** Никакой анимации размеров и раскладки.
- **Нативный скролл.** Без перехвата колеса и плавного скролла. GSAP + ScrollTrigger грузятся динамически после гидратации; WebGL не используется — сцена двумерная и бумажная, WebGL не даёт ей ничего, кроме веса.
- **Без JavaScript и с `prefers-reduced-motion: reduce`** — показывается финальная композиция. Скрипт не запускается вовсе, а CSS-переходы сводятся к 0.01 мс.
